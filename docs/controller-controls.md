# 电量与音频控制（0.1.5-dev，未发布）

## 电量

主窗口约每 5 秒刷新。桥接后端从原有输入转发路径中保存电量字节和单调时钟时间戳；管理器复用连接健康检查的私有管道请求，最多每 5 秒保存一份可丢弃的界面遥测。不会发送额外 HID 查询，也不为电量创建新的收发线程。

原生 USB／蓝牙模式在共享只读句柄上读取一个报告，超时 350ms，每次间隔至少 5 秒；进入桥接前取消并等待该读取退出。不会写输出报告、切换到增强模式、重新配对或唤醒手柄。原生蓝牙简短报告可能没有电量，此时显示“当前报告未提供电量”。电量来自粗略档位，并非逐百分点精度；断连、未知状态或过期报告显示不可用。

报告布局和电量状态参考 [SDL 的固定版本 SDL_hidapi_ps5.c](https://github.com/libsdl-org/SDL/blob/a45cd584df4dcd6fefb2c54b616158d3663a2883/src/joystick/hidapi/SDL_hidapi_ps5.c)。独立实现只解析完整 USB 报告或通过 CRC 检查的蓝牙控制报告。

## 默认扬声器静音

后端进程初始化为静音；初始化、状态和音频报告在实际 HID 写入前过滤扬声器音量／静音字段并重算 CRC。排队中的游戏报告不能在静音启用后重新打开扬声器。保留游戏原始状态副本，取消静音时发送一次状态报告，恢复游戏的原始音量和静音值；游戏自身静音时，取消工具静音不会强制发声。

只控制手柄扬声器，保留触觉数据、自适应扳机、灯光、麦克风和 3.5mm 耳机字段。不对四声道虚拟 USB 音频设备调用系统静音，因为其中另两声道携带精细触觉。后端私有管道明确确认设置后，主窗口才显示“已应用静音”。设置只在当前运行和会话内生效，下次打开工具仍默认静音。

报告结构沿用 [vDS 固定提交](https://github.com/hurryman2212/vds/tree/ec531599dfdd02e14ce68efd8c0d2dcb439894a5)；本项目过滤器见 `patches/controller_preferences.hh`，生成补丁见 `scripts/backend_preferences_patch.py`。既有 3 块预缓冲、35ms 启动超时、12 块突发上限、100ms 过期策略均保持不变。

## Bose 音量问题的诊断边界

主窗口每秒读取 Windows 默认播放设备、主音量和静音状态。“导出检查结果”包含当前所有活跃播放端点的音量及三个默认角色。读取发生在界面进程的后台任务，不在手柄输入或音频发送线程中；不拦截键盘，不设置系统音量，不打开麦克风。

短时只读观察命令：`DualSenseBridge.exe --volume-watch <该程序 .local 目录内的 JSONL 绝对路径> <1～120 秒>`。数据包含设备标识，不录制声音。每 250ms 记录一次，建议保持 Bose 播放同一段音乐，在原生／桥接状态分别用 Windows 音量键调低再调高，同时记录实际听感。

参考 [Microsoft IAudioEndpointVolume](https://learn.microsoft.com/en-us/windows/win32/api/endpointvolume/nn-endpointvolume-iaudioendpointvolume)：软件音量对独占流的作用与硬件音量能力有关。当前没有证据证明本次 Bose 问题来自独占模式、绝对音量或 AVRCP；不会据此擅自修改蓝牙注册表、服务或驱动。默认设备正确和音量数值变化都不能单独证明音箱响度变化。

## 验收范围

软件检查覆盖电量解析、报告 CRC、断连与过期数据、静音涉及的三种报告格式、其余字段逐字节保留、静音幂等性、麦克风命令隔离、私有管道偏好确认和非法请求拒绝。物理静音、恢复声音、触觉／扳机并存、Bose 音量键和桥接退出恢复必须另做实机验收。此前版本的成功不能替代这些新增功能的验收。

自然待机故障仍单独按 [重连调查](reconnect-investigation.md) 验证，不用手动关机替代自然待机。
