# 0.1.5-dev.2 音频保护候选版

日期：2026-11-02。基于界面版本 `b77979c`，承接 [静态审查](audio-isolation-static-review.md)。这是独立候选版，尚未发布，也未替换已验证的可用程序。

本轮完成确定性代码修正与软件验收。没有外接手柄／蓝牙耳机条件，因此没有启用真实桥接、输出手柄反馈、安装驱动或修改系统音频与蓝牙设置。**软件检查不能保证游戏识别、实际触觉和无线音频在所有环境下无回归。** 在以下实机门槛通过前，不把候选版替换为日常使用版本。

## 已实现的改动

### 1. 分离虚拟手柄内部的播放与录音控制

原后端将扬声器 Feature Unit 2 与麦克风 Feature Unit 5 的静音／音量保存在同一份状态里。现在两者独立，并按既有 USB 描述符校验控制接口、实体、主声道、选择器及数据长度。保留原有的音量范围和步进。

播放仍为 48 kHz、16 bit、四声道。USB 增益只处理前两个音频声道，后两个精细触觉声道逐字节保持；录音增益仅处理两声道麦克风 PCM。界面的“手柄扬声器静音”仍沿用已有最终写出过滤逻辑，没有把整个四声道端点静音。

这修复的是虚拟设备内部语义，**不等于修复 Bose 的 AVRCP／响度同步**，也不代表麦克风和 3.5mm 功能已实机验收。

### 2. 音频系统卡住时仍可发出停止信号

Core Audio 查询与默认设备保护移入同一程序启动的隐藏子进程，通过私有标准输入／输出通信；不创建常驻服务。正常请求时限 5 秒，停止观察采用更短预算。超时或取消后结束并回收该子进程，失败的客户端不会自动反复重启。

会话管理器每约 100 ms 独立检查停止请求与主窗口进程状态，直接发出既有后端停止事件；最终清理先发停止信号，再做诊断。不再等待音频 COM 调用返回后才通知后端停止。结束子进程可防止卡住的客户端稍后继续发出策略调用，不能撤销已经进入 Windows 的调用。

界面音量显示使用只读音频子进程，不接受默认设备写入。查询失败显示“读取暂不可用”，不会误报成耳机断开。手动“检查连接”可重新建立失败的只读观察进程。

代价是程序运行期间增加少量进程和 IPC：通常界面一个只读子进程，启用桥接时另有一个会话音频子进程；检查连接可能短暂增加一个。退出或父进程消失时由 Job Object 回收。没有新增安装依赖、开机项或后台系统服务，IPC 不在输入／触觉流转路径上。异常时优先停止桥接并报告，不能用这些改动保证系统音频自身恢复正常。

### 3. 保留用户最近选择的外部音频设备

保护器按播放／录音及各默认角色记住最近观察到的有效外部设备。用户从耳机 A 切到音箱 B 后，若新建虚拟 DualSense 抢到默认角色，恢复目标为 B。写入前重新确认当前默认仍是那个虚拟端点，避免覆盖检查期间用户刚做的切换。

原有归属检查保留：只处理启动后新增、确认为本机 USB/IP 虚拟 DualSense 的端点；原生 USB 手柄或归属未知的设备不作为默认纠正来源。目标失效时不强制切回。没有操作 Bose 音量、静音、采样格式、麦克风、蓝牙适配器或服务的新增代码。

**保护仍属于抢占后的纠正，最后一次检查与策略写入之间仍有竞争窗口。** 本版没有实现“从枚举第一刻起绝不成为默认端点”，也不加快原有保护轮询频率。

## 保持不变的桥接路径

- 实体输入解析、按键／摇杆／扳机／触控转发与 HID 排队。
- 自适应扳机输出、最终归零／释放、蓝牙 HID 写出与 CRC 路径。
- 触觉预缓冲 3 块、35 ms 启动超时、12 块容量、100 ms 过期限制，以及已有 pacing 和异步诊断机制。
- USB VID/PID、设备版本、描述符、端点、格式和接口结构。只在后端能力声明增加 `independentAudioControls`，避免新管理器误用旧后端。
- 原有反馈／延迟测试信号、设备租约、设备隐藏与恢复规则、默认不开机自启。

## 严格默认设备隔离的后续门槛

Microsoft 提供 [PKEY_AudioDevice_NeverSetAsDefaultEndpoint](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/pkey-audiodevice-neversetasdefaultendpoint)，需结合音频驱动 INF 的端点属性和关联配置。该属性不能简单等同于“创建后设一次默认输出”。设备接口与属性部署方式见 [音频设备接口安装](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/installing-device-interfaces-for-an-audio-adapter) 和 [INF AddReg](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/inf-addreg-directive)。

当前虚拟设备与实体 USB DualSense 共用硬件标识，不能发布仅匹配 `VID_054C&PID_0CE6` 的通用策略。下一阶段必须依次验证：

1. 确定仅匹配本工具虚拟音频接口的受支持身份／安装方法，不影响实体 USB 手柄和其他 USB/IP 设备。若需改变版本或标识，先验证游戏 SDK、四声道端点发现及原生识别的兼容性。
2. 在隔离环境验证 INF、签名、安装／卸载和回退；策略须在首次端点出现前生效，覆盖播放与录音全部默认角色。不可依赖事后编辑全局 MMDevices 注册表。
3. 首次枚举、再次启用、手柄断开、自然待机及重连均不能抢默认输出；游戏显式打开的四声道流必须继续工作。
4. 向用户展示已验证的具体驱动包和影响，再按本任务约定获得安装确认。策略没有完成这些验证前保持不安装、不启用。

不能通过禁用整个虚拟播放端点、改变整个端点的系统音量、重启蓝牙适配器、音频服务或耳机设备来代替上述隔离。

## 替换可用版本前的实机验收

同机保留旧版，以相同游戏／测试信号对照候选版：

1. 游戏关闭时，原生 USB 与原生蓝牙的输入、耳机播放和键盘音量键各做基线。耳机音量若原生模式也失效，单独记录，不归因于默认端点纠正。
2. 蓝牙桥接检查全部输入、左右精细触觉、R2 阻力、取消归零、默认扬声器静音及电量；再进《影之刃：零》对照游戏识别和反馈。
3. 耳机持续播放，检查三类默认播放角色、录音角色、音量读数与实际响度；主动切换外部输出后确认选择得到保留。
4. 正常停止、关闭窗口、手动关机重连和**真实自然待机**分别验证。自然待机不能由手动关机替代；重连必须手动启用新会话，界面与实际连接一致。
5. 停止后确认后端和子进程退出、虚拟端口移除、实体输入恢复，再用 USB 验证原生连接。旧版目录和会话恢复记录保留，发生回归时先正常恢复再换回旧版。
