# 0.1.5-dev.4：退出后的灯光与残留核对

> 历史候选版记录；功能代码已随 [v0.1.5](releases/v0.1.5.md) 正式发布，下文保留候选版验收时的状态。

日期：2026-11-02。系统环境恢复只撤销本次桥接拥有的变更，不覆盖用户或其他软件在运行期间做出的修改。本版基于 dev.3，未发布，也未覆盖旧候选版。

## 本次故障与修复

用户在 dev.3 点击停止后仍看到黄色灯光。现场记录显示本次后端已退出、USB/IP 端口已移除、HidHide 与启用前一致，原生蓝牙输入和 Bose 默认输出可用。因此黄色残留是手柄侧输出状态未释放，不能仅凭灯色推断桥接仍在运行。

原退出报文归零震动、释放扳机、关闭麦克风流，但刻意保留了最后的 RGB 和玩家灯状态。本版在原有清理之后增加两条只控制灯光的报文：先释放主机灯光并清除桥接／游戏的玩家指示灯，再请求固件恢复原生蓝牙灯光。不写入一个猜测的蓝色 RGB 值，也不重启蓝牙、音频服务或手柄。

两条终止灯光报文绕过常规扬声器静音过滤，否则过滤器会给灯光报文附加音频／静音字段。常规桥接输出仍保持原有过滤行为。每个退出报文独立尝试，一步失败不会跳过后续步骤；只有相应写入都成功，才记录震动／麦克风或灯光的成功标记。灯光标记缺失时，主窗口提示设备状态待确认。

协议字段核对参考 [SDL 的 DualSense 实现](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapi_ps5.c)、[dualsensectl 的原生灯光开关](https://github.com/nowrep/dualsensectl/blob/main/main.c) 和 [RPCS3 字段定义](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Input/dualsense_pad_handler.h)。本项目独立实现报文构造；这些资料只用于核对协议事实，没有引入其源代码或新增运行依赖。

## 现场验证及边界

- 用户确认启用前为蓝色常亮。
- 单独发送 LED release 后，用户确认灯光熄灭。这只能证明释放有效，不能视为恢复原样。
- 随后仅发送原生灯光开启请求，用户确认蓝灯恢复，Bose 正常。
- `IOCTL_HID_GET_OUTPUT_REPORT` 查询返回了长度，但除报告 ID 外没有有效状态，包括蓝灯／黄灯对应的 RGB 信息。不能把该结果当作启用前快照；实验查询没有加入正式启动路径。
- 集成后的 dev.4 正常停止与直接关闭窗口两条路径均完成实机验证。用户分别确认蓝灯、Bose 和音量调节正常；关闭窗口一轮还验证了精细触觉与自适应扳机。两次会话日志都确认输出归零／麦克风关闭、两条灯光指令写入及对应虚拟端口移除，恢复警告为空。
- 238 项 C# 检查、原生后端检查和 4 项补丁兼容性检查通过，包含灯光报文没有夹带音频／扳机／自定义 RGB 字段、CRC、时序和灯光失败独立提示。USB/IP 实现与协议编解码文件哈希未变；dev.3 程序保持原样。
- 关闭窗口后额外观察约 95 秒，19 次只读采样全部读到原生蓝牙输入，恢复警告为零。最终现场核对无桥接进程、虚拟手柄、导入端口或待恢复会话，默认输出仍为 Bose，HidHide 与本次启用前一致。此结论只覆盖本机这两轮会话，不能外推为任意设备及故障下的保证。

## 其他状态的恢复范围

| 项目 | 处理与限制 |
| --- | --- |
| HidHide | 只解除本次隐藏的手柄、撤销本次登记；共享配置被其他软件改动时保留其修改并报告冲突，不整表回滚 |
| USB/IP、后端 | 只移除本次端口、结束本次进程；退出后回读核对，不能仅凭窗口关闭宣称成功 |
| 系统音频 | 仅纠正被本次虚拟手柄端点抢占的默认角色，保留用户最新外部输出选择；不回滚用户音量，不重置 Bose 或适配器 |
| 震动、扳机、麦克风流 | 沿用既有归零、释放和关闭；控制器掉线时不能保证最后报文送达，需报告未确认 |
| RGB、玩家灯 | 清除桥接／游戏灯效，交回固件原生灯光；本次已确认普通原生蓝灯场景。启用前其他软件的任意自定义 RGB／亮度／玩家灯不可可靠读回，不能声称精确恢复 |
| 麦克风静音按钮 | 保留会话中用户的静音选择；关闭麦克风流不等于把用户的静音偏好强制改回旧值 |
| 手柄音频字段 | 停止桥接音频输出与采集；不声称已取得并恢复每个固件内部增益、路由和节能位的启动前快照。原生 USB 再用仍需实测 |
| 蓝牙报告格式 | 退出后仍可能保持增强报告格式。它不表示虚拟 USB 仍在运行，也不等于刚上电的简化报告状态；本版不强制手柄断连。SDL 同样将增强模式视为连接内不可直接逆转的状态 |
| 已安装依赖、历史设备记录、日志 | 驱动是此前安装并已存在的依赖；Windows 可能保留不活动的枚举缓存，工具保留诊断日志。不会在每次停止时卸载驱动、清注册表或删除共享设备历史 |

因此，本版能清理已确认的黄色灯光残留，并对工具拥有的系统变更执行定向恢复；**不能宣称对任意启动前的手柄固件状态做了完整快照及逐字节回滚**。正常停止和关闭窗口已通过本轮检查；自然待机／唤醒和原生 USB 回退尚未针对 dev.4 复测。

候选目录：`dist/DualSenseBridge-controller-recovery-candidate`。输入解析、USB 身份、正常蓝牙写出队列和触觉缓冲参数未改变。
