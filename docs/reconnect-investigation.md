# 断连与音频排查：0.1.5-dev 候选版

截至 2026-10-31（Asia/Shanghai），本文件记录本地开发候选版，尚未发布。GitHub v0.1.4 已转为正式 Release / Latest，原说明、附件及标签所指代码保留。

## 已确认与未确认

- 用户报告游戏保持运行、电脑没有睡眠，仅手柄静置后自动关机。重新连接时下拉框显示蓝牙，游戏仍有反馈，同时 Bose 无声。
- 下拉框原本描述实体连接方式，不能单凭它判断游戏是否正在使用虚拟 USB 桥接。
- 原会话日志记录了手柄断开及后端退出；清理前的音频采样中，Bose 播放端点已不可用。记录不足以确定 Bose 首次失效相对手柄断连的先后顺序，也不能证明桥接与故障无关。
- 故障延续到桥接进程和虚拟端口均不存在时。局部重连没有恢复立体声，用户重启电脑后恢复。这支持继续排查蓝牙音频状态，但不是确定根因。
- 重启后，原生蓝牙以及原 v0.1.4 桥接各完成一次手动关机、约 15 秒后重连。用户均确认 Bose 一直正常。桥接轮次配置清理完成，后续原生输入可读，虚拟端口已移除。
- **手动关机不等同于自然待机。** 本次短时测试不覆盖长时间游戏输出、静置计时或长期蓝牙共用，不能据此宣称原故障已修复。

## 候选版改动

1. 主窗口明确区分“实体连接”和桥接会话状态。检查到后端、虚拟手柄或导入端口时，不再直接显示原生模式；无法完成检查时显示待确认。没有默认播放设备时禁止新建桥接。
2. 修正后端与管理器的重连竞争：原后端每秒尝试重新创建连接，管理器约 5 秒后才结束断连会话。候选版在连接工作线程结束后退出监督循环，重新连接需要手动启用新会话。代价是短暂断连也不会在后台自动接管；这是会话行为修正，不是蓝牙音频修复证明。
3. 会话在设备清理和恢复观察后保存 `audio-timeline.json`：复用管理器已有音频采样，在状态变化或约 30 秒心跳时在内存记录默认设备和启动时端点可用性，最多保留 256 条。不会在默认音频修正或后端停止信号前增加诊断文件写入。它不录制声音，不修改 Bose 或其他设备设置；仍受采样间隔和诊断落盘条件限制，断电或进程被强杀时这份内存记录可能丢失。

没有改变触觉预缓冲、发送节奏、扳机协议或系统驱动。没有加入开机任务、常驻服务或全局蓝牙重置。音频时间线的文件写入在会话管理进程中，未加入手柄收发线程。

## 下一次自然待机验收

1. 游戏关闭时启动候选版，确认 Bose 正常播放，再手动启用桥接。
2. 使用原故障场景进入游戏，保持游戏和 Bose 播放，记下最后一次操作手柄的时间。
3. 放下手柄等它自行关闭，不用人工关机替代；记录是否先发生 Bose 无声。
4. 按 PS 键重连，先观察主窗口会话状态、原生输入与 Bose。桥接不应自动重新建立。
5. 退出游戏后再手动启用桥接并验证反馈。游戏对控制器热拔插的处理单独记录，不把普通蓝牙输入恢复当作游戏已重新识别。

若 Bose 再次失效，先记录发生时间和主窗口状态，正常退出游戏、停止桥接后保留音频时间线、恢复记录和后端日志，再安排其他恢复，避免把重启后的正常状态当成故障现场。
