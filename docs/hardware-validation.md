## 实机发现并修复

1. USB/IP 根控制器实例为 ROOT\USB\0000，硬件 ID 才是 ROOT\USBIP_WIN2\UDE。原先误用实例名判断，造成音频归属检查拒绝并自动停止。现在结合根设备、精确硬件 ID 和 usbip2_ude 服务确认归属；未放宽到一般 USB 控制器。
2. 新音频端点晚于 HID 握手出现。桥接现在等待枚举和默认输出纠正稳定后才报告已连接。
3. HidHide 控制句柄可能被并发只读检查短暂占用。控制访问仅对明确的 0x0005 开启有限重试，持续失败仍停止和恢复。

第二轮早期记录曾观察到虚拟手柄音频短暂成为默认输出并随后被恢复，因此不能声称每台电脑绝无瞬时默认切换。最终验收记录增加了连接成功后的运行中音频核查。
Windows 对新音频端点的默认选择说明：https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/default-audio-endpoint-selection

## 如何证明高级反馈

PS 图标、按键输入和一般震动不足以证明高清触觉或自适应扳机。
需要同一游戏版本、同一存档/动作/反馈设置下，比较工具停止时的物理 USB 原生与拔线后蓝牙桥接：
- 扳机：相同动作是否具有相近的阻力起点、持续范围、强度和动态变化。
- 触觉：相同动作或场景是否保留左右分布、细节、时序和可感知延迟。
- 系统侧：区分一般 HID 输出、真正启用的自适应扳机效果以及非静音的触觉音频流。
- 共存与恢复：耳机持续播放、正常停止后恢复原生，再插 USB 验证输入。
如果 USB 原生基线不产生某项反馈，该场景不能用于判断桥接是否实现该功能。
