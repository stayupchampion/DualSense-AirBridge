# 普通诊断日志与锁占用优化（0.1.4）

本轮目标是减少诊断工作给手柄收发造成的偶发等待。继续使用 0.1.3 已实机验证的 3 块预缓冲（32ms PCM 音频量）、35ms 启动超时、12 块突发容量及 100ms 过期上限；不修改蓝牙发送节奏、触觉波形、扳机协议、系统驱动或退出恢复策略。

## 实现

- 收发路径的普通 Info/Debug 诊断进入单独的后台线程。固定容量为 256 条，每条最多 4096 字节正文，储存约 1MiB。入队使用 try-lock；队列满、瞬时锁竞争或消息过长时跳过普通日志并统计，不等待日志文件。队列工作线程不持入队锁执行文件 I/O。
- Warn/Error 仍走直接写入；启动、退出归零、恢复相关记录没有改成可丢弃的普通诊断。拥堵计数由后台线程写成警告。因此这不保证错误路径完全没有日志等待，也不能保证磁盘故障时日志仍能落盘。
- 日志保留提交时刻，后台写入可能晚于后来的直接写入记录；分析应按每行时间戳，不能把文件行顺序当成事件顺序。已有触觉统计脚本逐行按时间戳过滤，可继续使用。普通统计行可能缺失，未出现某条日志不能等价于事件没有发生。
- 周期触觉统计和 HID 写入统计在各自锁内只捕获所需字段、更新计数，在锁外拼接文字；首帧音频日志也移到状态锁外。
- 缺数据警告移到状态锁外，但原有停止音频路由报告先发送，再写警告，避免慢日志扩大旧状态覆盖新音频流的时序窗口。
- 后端退出时先完成原有控制器线程停止及归零；Logger 析构排空已接收的诊断并 join 日志线程，不遗留后台进程或分离线程。

新增一个仅在后端存活时运行的日志线程及约 1MiB 队列内存。极端情况下可能少几条普通诊断；异常退出时尚未写出的普通诊断也可能丢失。排空是条数有界，不代表磁盘异常时耗时有硬上限；会话管理器原有退出截止时间仍适用。

## 验证边界

软件验证包括：堵塞日志接收端时生产线程仍能返回、队列容量/FIFO、多个并发生产者、退出排空、写入回调异常隔离、关键记录直接可读、日志文件重开，以及生成补丁前后日志字段名保持一致。原有输入请求取消、旧会话回复隔离、音频队列和归零检查继续执行。

这些软件验证只证明日志与控制数据的隔离行为，不是手柄物理延迟测试。本轮不承诺平均延迟再降低某个毫秒数。0.1.3 用户已反馈游戏体感接近 USB；本轮另行完成了下述 0.1.4 实机验收。

## 使用与恢复

公开发布只提供当前 0.1.4；旧开发包不分发。切换版本或回到原生连接前，先退出游戏，正常停止桥接并确认恢复，关闭窗口。保留程序目录中的既有恢复记录，未完成恢复时不要删除 `.local/`。不要同时启用两个版本。

代码入口：`scripts/backend_diagnostics_patch.py`、`patches/diagnostic_worker.hh`；测试：`tests/backend_diagnostic_tests.cc`、`tests/test_diagnostic_patch.py`。
